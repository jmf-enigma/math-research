# Strategy Scheduler

Use when routes genuinely compete or failure repeats. Keep the ordinary single-route proof loop otherwise. This file owns route allocation and decomposition; use [structural discovery](proof-idea-generator.md) to invent a missing object.

## Choose the next artifact

| Current evidence | Next move |
| --- | --- |
| A required obligation became smaller, or a new checked premise makes it tractable | Continue that node |
| A stable statement has one identifiable bad inference | Repair that block, preserving the checked prefix |
| A child hides the construction, restates the parent, or is not consumed | Re-decompose after checking conditional assembly |
| The route lacks a likely standard premise | Retrieve its exact statement and assumptions |
| A boundary instance, identity, witness, or certificate can decide the kernel | Run that check before extending the proof |
| The same obstruction returns without a new mathematical input | Change representation or retire the route |
| No live route has a feasible decisive check | Report the exact gap and strongest checked partial result |

Rank moves by how much their result can prove, refute, or redirect, then by cost and relevance to the final assembly. Elegance, retrieval rank, model confidence, and number of agents have `proof_effect=none`.

## Portfolio Routes

Branch after materially different failures or a serious attempt with no central object. Keep only alternatives that differ in mechanism, central object, certificate, or failure world. For example, a coupling and a dual certificate may be independent attacks; renamed versions of the same missing inequality are not.

Seed independent attacks with the theorem, allowed premises, and output contract. Do not preload the favorite sketch. Each returns its mechanism, kernel, cheapest falsifier, and conditional assembly. Compare artifacts before sharing useful pieces across branches.

Expand the route with the strongest conditional assembly and cheapest decisive test. Give an incompatible shadow family a bounded probe while the leading kernel remains unresolved; it need not receive equal effort. Once one stable child controls the route, focus on that child and postpone siblings a replan may discard. Roles are a menu, not fixed quotas.

Mark a family saturated when independent attacks return the same obstruction without a new artifact. Reopen only for a new premise, representation, construction, or checker. Before stopping, consider an underexplored family only if it has a cheap decisive probe. Exhausting the favorite is not exhausting all routes, but speculative alternatives do not justify endless search.

## Exact Symmetry Quotient

Merge routes related by a proved transformation preserving the entire statement. Account for exchanged assumptions and boundaries. Transport a result only through the required inverse or return implication and replay it on the original target. Approximate symmetry is a search hint, not equivalence.

## Decomposition Admission

Admit children only when all of these hold:

- **Parent sufficiency:** assuming the children, the parent follows with its original quantifiers and definitions.
- **Consumption gate:** each required child has a use site; after proving it, replay the parent using the actual result. `proof_doctor.py` blocks further child work while this active gate is incomplete or a proved required child lacks a passed replay.
- **Strict simplification:** each child removes a genuine difficulty and has a plausible way to be proved, refuted, retrieved, or checked.
- **Acyclicity:** no child depends on the parent or an equivalent ancestor.
- **Local repair:** a failed child should identify the affected dependencies rather than force an unexplained rewrite of the whole proof.

Distinguish assumptions needed to state a child from premises used to prove it. Defer unused lemmas unless they actively test or repair the route. A type-correct sketch can still fail this mathematical admission test.

## Information-Ordered Representation Switch

An exact checker result or replayable witness can decide its stated scope. Exhaustive finite evidence concerns that finite domain; sampled absence and model critique only guide search. An exact counterexample to an auxiliary construction need not refute the parent theorem.

Choose the new object from the failure: boundary failure suggests endpoint or KKT conditions; compensating terms suggest a joint residual or telescope; a quantifier mismatch suggests a witness or uniformization lemma; failed recursive closure suggests an extra state variable. Changing the prompt, notation, temperature, or worker does not change the mathematical route.

For retries, use a solver-owned attempt digest: current statement, checked prefix, first failure, exact checker output, and changed input. Downstream claims after an invalid inference remain unchecked. Guarded proof-template reuse requires matching preconditions, a substitution map, and replay of the instantiated proof.

## Progressive Budget Grants

For expensive work, reserve enough budget to replay the winning artifacts, assemble the theorem, and review the complete proof. Fund exploration up to a named decisive artifact. Renew only for checked progress, a smaller gap, or a new input making the next check informative. Do not consume the verification reserve to prolong an unchanged route.

Keep a discarded state only if it contains a checked prefix and was pruned before a decisive check or has gained new evidence. Revisit it for that reason; retire it if the probe leaves the obstruction unchanged. Historical storage is not a license to repeat failed work.

## Stage-Conditioned Strategy Trial

Use only when route allocation itself repeatedly fails across a long project. Compare guidance on the same frozen theorem, proof state, allowed evidence, tools, and budget. Measure returned mathematical artifacts and obligation changes; relative scores only schedule trials. Require matched-baseline improvement and a held-out proof state before reusing guidance. Keep these local experiments out of the global skill during an active run.
